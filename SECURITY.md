# Security Policy

## Supported Versions

Zero follows SemVer. The latest stable `0.5.x` line receives security fixes.
Older lines are unsupported once a newer `0.5.x` is published. See
`docs/PUBLIC_API.md` for the current API freeze and compatibility window.

| Version | Supported |
| ------- | --------- |
| 0.5.x   | ✅        |
| < 0.5.0 | ❌        |

## Reporting a Vulnerability

**Do not open a public issue for security problems.**

Please report privately so we can ship a fix before public disclosure:

- Email the maintainers at **security@zerofmk.in** (replace with the real
  disclosure address), or
- Use GitHub's private vulnerability reporting on the repository.

Include:

- A description of the vulnerability and impact.
- Steps or a minimal PoC to reproduce.
- The affected Zero version(s) and Zig version.

We acknowledge receipt within **3 business days**.

## Fix Window

- **Critical / RCE-class**: fix and release within **7 days** of a confirmed,
  reproducible report.
- **High**: within **30 days**.
- **Moderate / Low**: within the next scheduled `0.5.x` patch release
  (target **90 days**).

We will coordinate a disclosure date with the reporter and credit them unless
they request anonymity.

## Releases Are Signed and Verifiable

Every GitHub Release ships:

- The two prebuilt binaries (`zero-<target>.tar.gz`) for
  x86_64/aarch64 on Linux.
- A `*.sha256` checksum file per binary.
- Detached GPG signatures (`*.asc`) produced by the release key.
- `final-sbom.json` — a merged CycloneDX SBOM (source + compiled binary),
  generated by the `sbom` job in `.github/workflows/release.yml`.

Verify a download before running it:

```bash
sha256sum -c zero-x86_64-linux.tar.gz.sha256
gpg --verify zero-x86_64-linux.tar.gz.asc zero-x86_64-linux.tar.gz
```

The SBOM can be scanned with Grype or uploaded to Dependency-Track:

```bash
grype sbom:final-sbom.json
```

## Dependency and Supply-Chain Notes

Zero vendors its Zig/C dependencies under `zig-pkg/` and links a small set of
system libraries (`librdkafka`, `libduckdb`, OpenSSL) optionally — see
`build.zig` feature flags (`-Dkafka=false`, `-Dduckdb=false`) to build a
minimal binary without them.
